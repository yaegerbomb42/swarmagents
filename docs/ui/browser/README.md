# Live browser viewer — artifacts

Generated by `npm run test:browser:capture` (`tests/browser-capture.mjs`), which drives the local
fixture site with the real runtime and saves what the live panel streams.

| File | What it shows |
| --- | --- |
| `viewer-before-modal.jpg` | CDP screencast keyframe before a modal opens |
| `viewer-modal-open.jpg` | the same page with the modal open |
| `viewer-after-confirm.jpg` | after the agent confirms the dialog |
| `viewer-multistep-form.jpg` | the agent part-way through the 3-step form |
| `session-replay.jsonl` | the bounded replay log the runtime keeps for "replay what happened" |

## How the stream works

- Source: CDP `Page.startScreencast` (JPEG, quality 60) on the active page of the task's browser.
- Transport: authenticated HTTP chunked stream (`text/event-stream`) at `/api/browser/stream?session=…`,
  throttled to ~12 fps. Frames carry the CDP timestamp, so the panel can show real frame delay (the
  local test asserts **< 500 ms**; measured ≈ 3 ms).
- Control: `POST /api/browser/control` carries take-over / hand-back / pause / resume / stop, plus the
  user's mouse and keyboard events while they hold control. Input is rejected (409) while the agent is
  driving.
- Auth: both routes are wrapped in `scoped()` and resolve the task from the caller's own store, so only
  the owner of a task can watch or drive its browser. Anonymous calls get 401 in server mode.
